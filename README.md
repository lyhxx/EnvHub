# EnvHub

Windows 本地开发环境管理器。集中查看本机已安装的运行时与版本、切换默认版本、按官方源下载安装新版本，并读写包管理器使用的镜像与缓存配置。

## 简介

一台 Windows 开发机上，Python、Node.js、JDK、Go 常常装了不止一套：PATH 里堆着多份同名目录，切换版本靠手改环境变量，改完还得记着别把系统变量弄坏；包管理器的镜像和缓存分散在各自的配置文件里。

EnvHub 把这些收进一个界面：扫描出本机有什么、把某个版本设为默认、需要新版本时按官方源下载安装，顺带读写 npm / pip / Maven 的镜像与缓存配置。

几项设计取向：

- **本机优先**：不登录、不上报、无账号体系，全部数据存放在本机 JSON 文件里
- **写入可撤销**：改动环境变量、软件源配置、数据目录之前都保存快照，可逐条恢复
- **默认不动系统**：只写当前用户级环境变量；需要改系统 PATH 时先说明原因，并在确认后才执行
- **只认官方源**：版本清单来自各项目官方发布源，下载校验值也只取官方发布的哈希
- **安装有门槛**：只有官方同时提供 ZIP 归档与校验值（SHA-256 / SHA-512）的环境才开放应用内安装

## 功能

| 模块 | 说明 |
| --- | --- |
| 环境检测 | 扫描 PATH 与常见安装目录，识别 13 个开发环境的版本；也可指定可执行文件手动登记 |
| 环境概览 | 词云展示全部环境，已检测到的按品牌色显示、未检测到的灰显，点击进入详情 |
| 版本清单 | 列出每个环境的全部版本、安装路径与来源（系统原有 / 手动登记 / 托管安装） |
| 默认版本切换 | 把所选版本目录排到用户 PATH 最前；JDK 同步更新 `JAVA_HOME`；写入前保存快照，可逐条撤销 |
| 遮蔽处理 | 检测系统 PATH 中排在更前的同类目录，经确认后移除这些遮蔽项（只删除、不新增） |
| PATH 体检 | 清理用户 PATH 中的重复条目与指向不存在目录的条目 |
| 可用版本 | 读取各项目官方发布源，列出可安装或可下载的版本与校验值 |
| 应用内安装 | 下载 → 校验 → 解压到托管目录 → 探测可执行文件与版本 → 登记；失败自动回滚 |
| 下载管理 | 并发 3、暂停与 Range 续传、取消、重试、删除任务（可选同时删除文件） |
| 手动导入 | 官方提供校验值的 ZIP 归档可导入并与官方哈希比对；官方无校验值时不做导入 |
| 软件源与缓存 | npm（`.npmrc`）、pip（`pip.ini`）、Maven（`settings.xml`）的镜像地址与缓存 / 仓库目录读写 |
| 网络代理 | 跟随系统 / 直接连接 / 自定义（http、https、socks4、socks5），带连接测试 |
| 数据目录 | 默认 `%LOCALAPPDATA%\EnvHub`，可在设置中迁移（跨磁盘流式复制并显示进度） |
| 异常恢复 | 提示上次异常退出；清理中断留下的半成品安装目录；未完成的下载恢复为暂停 |
| 外观 | 浅色 / 深色 / 跟随系统；侧边栏可折叠 |

## 版本源

每个环境的「可用版本」都读取官方发布源。**所有环境的版本都可以下载**：满足"官方 ZIP + 官方校验值"的环境可以在应用内直接下载并安装；其余环境提供官方直链，可复制链接或用浏览器下载，安装完成后由 EnvHub 识别或手动登记。

| 环境 | 版本源 | 下载方式 |
| --- | --- | --- |
| Node.js | nodejs.org 各 LTS 线 | 应用内下载 + 安装 |
| Bun | GitHub Releases（oven-sh/bun） | 应用内下载 + 安装 |
| Java / JDK | Adoptium Temurin 25 / 21 / 17 / 11 | 应用内下载 + 安装 |
| Go | go.dev 官方版本 JSON | 应用内下载 + 安装 |
| Maven | 官方元数据 + archive.apache.org | 应用内下载 + 安装 |
| Gradle | 官方 versions JSON | 应用内下载 + 安装 |
| Python | python.org 官方目录 | 官方直链（浏览器下载） |
| Rust | GitHub Releases（rust-lang/rust） | 官方直链（浏览器下载） |
| .NET | 官方 releases-index | 官方直链（浏览器下载） |
| PHP | windows.php.net | 官方直链（浏览器下载） |
| Ruby | RubyInstaller Releases | 官方直链（浏览器下载） |
| Git | git-for-windows Releases | 官方直链（浏览器下载） |
| Docker | 官网（由官方安装器维护） | 前往官网 |

应用内安装需要官方同时提供 ZIP 归档与校验值：Node.js、Bun、JDK、Go、Gradle 用 SHA-256，Maven 用 SHA-512。其余环境的安装器是 `.exe` / `.msi`，或官方未发布校验值，因此只提供直链；下载安装后 EnvHub 会识别到新版本，也可以用「手动登记」把可执行文件加进版本列表。

## 安装

下载地址：[Releases](https://github.com/lyhxx/EnvHub/releases)；也可以按下面的「开发」一节自行构建。

| 类型 | 文件名 | 说明 |
| --- | --- | --- |
| 安装版 | `EnvHub-0.3.0-setup.exe` | 安装到系统，可自选安装目录，创建开始菜单快捷方式 |
| 绿色版 | `EnvHub-0.3.0-portable.exe` | 免安装，双击即用；配置与运行时数据仍保存在用户目录，与安装版共用同一份 |

系统要求：Windows 10 / 11（x64）。程序自带运行时，无需另外安装 Node.js、.NET 或 Python。

## 使用

### 常用操作

| 操作 | 方式 |
| --- | --- |
| 扫描本机环境 | 概览页「扫描本机环境」，或环境页「↻ 重新扫描」 |
| 设为默认版本 | 版本页目标行「使用此版本」 |
| 撤销环境变量修改 | 设置 → 本机数据 → 撤销修改（恢复最近一次 PATH / `JAVA_HOME`） |
| 清理无效 PATH 条目 | 设置 → 本机数据 → 修复 PATH |
| 手动登记环境 | 环境与工具 → 右上「＋ 手动登记」，选中运行时的可执行文件 |
| 下载并安装版本 | 环境与工具 → 可用版本 → 「应用内下载」，随后在下载页点「安装」 |
| 导入已下载的 ZIP | 可用版本 → 「导入并校验」，选择浏览器下载的归档 |
| 配置软件源 / 缓存 | 环境与工具 → 软件源（npm / pip / Maven） |
| 更换数据目录 | 设置 → 本机数据 → 更改（可选是否搬移现有内容） |
| 处理系统 PATH 遮蔽 | 切换版本后按提示点「移除并生效」，需一次管理员授权 |

### 生效规则

| 规则 | 说明 |
| --- | --- |
| 生效 PATH 顺序 | 系统 PATH 在前、用户 PATH 在后。写入用户 PATH 不保证优先级，界面会按生效顺序判断并提示 |
| 写入目标 | 默认只写当前用户级环境变量；系统 PATH 仅在确认移除遮蔽项时改动，且只删除、不新增 |
| 生效时机 | 环境变量的修改对新开的终端生效，已经打开的窗口不受影响 |
| 托管版本位置 | `managedRoot\runtimes\<环境>\<版本>`，目录内带 `.envhub.json` 标记；标记为"安装中"的目录会在下次启动时清理 |
| 版本号比较 | 官方发布名与本地实际报出可能不同（例如 `21.0.12.1+1` 与 `21.0.12.1`），按前导数字段比较 |

### 数据与隐私

| 项目 | 位置 |
| --- | --- |
| 配置与记录 | `%APPDATA%\EnvHub\db.json`（原子写入，保留 `db.json.bak`） |
| 运行时与下载文件 | 默认 `%LOCALAPPDATA%\EnvHub\`，可在设置中迁移 |

程序不创建账户、不上报数据。联网请求只发生在版本源查询、文件下载、代理与镜像连接测试，且都由本机主动发起。

## 常见问题

**设为默认后当前终端没变化？**
环境变量只对新开的终端生效。若界面显示"未生效"，说明系统 PATH 中存在更靠前的同类目录，按提示点「使用此版本」→「移除并生效」即可。

**装完 Python 却不在列表里？**
先「重新扫描」；仍没有就手动登记，注意选**运行时的可执行文件**（`python.exe`），而不是下载的安装包（`python-3.14.0-amd64.exe`）。

**手动登记后把软件卸载了，记录还在？**
记录不会自动消失，点该行右侧 `···` 从清单移除（不会卸载软件）。若该目录已被写进 PATH，可用设置里的「修复 PATH」清理失效条目。

**提示"有 N 个版本目录缺少 EnvHub 标记"？**
这些目录不是 EnvHub 安装的，或者标记文件丢失。程序不会自动删除，只做提示，确认后可手动清理。

**为什么应用内安装只有 6 个环境？**
应用内安装需要官方同时提供 ZIP 归档与校验值，否则无法校验文件完整性。其余环境（安装器为 `.exe` / `.msi`，或官方未发布校验值）在「可用版本」里给出官方直链，可复制链接或用浏览器下载；装完之后 EnvHub 会识别到新版本，也可以用「手动登记」把可执行文件加进版本列表。

**首次安装提示"未知发布者"？**
安装包未购买代码签名证书，Windows SmartScreen 会给出该提示。点击「更多信息 → 仍要运行」即可。

**软件源"当前"显示的是默认位置？**
说明配置文件里没有对应键，显示的是该工具的默认路径，点「应用」后才会写入。

## 项目结构

```
src/
├── main/                    主进程
│   ├── index.ts             入口：单实例、会话锁、窗口、启动扫描
│   ├── ipc.ts               IPC 通道注册与参数校验
│   ├── runtime/
│   │   ├── service.ts       环境检测、当前版本解析、资产校验
│   │   └── catalog.ts       各环境的官方版本清单
│   ├── services/
│   │   ├── downloads.ts     下载队列、续传、校验
│   │   ├── install.ts       托管安装 / 卸载
│   │   ├── environment.ts   用户 PATH / JAVA_HOME、提权清理、修复与撤销
│   │   ├── storage.ts       数据目录切换与搬移
│   │   ├── packages.ts      npm / pip / Maven 配置读写
│   │   ├── network.ts       代理设置与连接测试
│   │   └── notifications.ts 主进程提示通道
│   └── storage/store.ts     本机 JSON 存储（原子写 + 备份）
├── preload/index.ts         contextBridge 暴露的接口（含错误信息整理）
├── renderer/                Vue 3 界面（概览 / 环境与工具 / 下载 / 设置）
└── shared/                  主进程与界面共用
    ├── contracts.ts         IPC 契约与数据类型
    ├── runtimeMeta.ts       环境元数据（名称、颜色、官网、搜索关键词）
    ├── downloadHosts.ts     各环境允许下载的域名
    ├── installable.ts       支持应用内安装的环境名单
    ├── versions.ts          版本号比较
    └── appInfo.ts           版本号
```

## 开发

- 环境要求：Node.js 20+，Windows
- 安装依赖并运行：`npm install && npm run dev`
- 其他命令：`npm run typecheck`（类型检查）、`npm run build`（编译到 `out/`）、`npm run dist`（生成安装包到 `release/`）

架构说明、IPC 通道、数据存储、环境变量写入约定与扩展新环境的方式见 [开发文档](docs/DEVELOPMENT.md)；版本变更见 [CHANGELOG.md](CHANGELOG.md)。
